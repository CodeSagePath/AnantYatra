TRIP-PLANNING TRAINING DATA SOURCE AUDIT
Reviewed: 2026-10-18
Pilot: Bengaluru anchor, target coverage up to 250 road-km

Decision

No reviewed, reusable request-to-itinerary dataset was identified in the
official Indian/Karnataka data sources checked. The available government
tourism datasets examined are useful for context or aggregate statistics, but
they do not provide user requests paired with accepted itineraries, routed
stops, preferences, or itinerary edits. Do not use them as trip-planning
supervision by themselves.

Source findings

1. Karnataka OGD: Tourists Footfalls into Karnataka

- Official catalog: https://karnataka.data.gov.in/catalog/tourists-footfalls-karnataka-3
- The entry is district-level yearly domestic/foreign tourist counts, published
  and last updated on 2021-12-03. It identifies one resource, titled
  "Karnataka Tourist Footfalls 2017".
- The catalog page says OGD-published datasets are licensed under the
  Government Open Data License - India (GODL-India). GODL-India permits users
  to use, adapt, publish, display, and create derivatives for lawful commercial
  and non-commercial purposes, subject to its conditions and attribution.
- Useful only for coarse popularity/context if its fields and source metadata
  prove relevant. It is not route, POI, or itinerary training data.
- Catalog license page: https://karnataka.data.gov.in/godl

2. Ministry of Tourism data portal

- Tourism statistics catalog: https://data.tourism.gov.in/tourismdata
- Raw-data listing: https://data.tourism.gov.in/rawdata
- The portal lists tourism compendiums/statistical reports and yearly data.
  The raw-data page lists year-based files (2019–2024 in the inspected view).
- These pages describe tourism statistics, not traveler-level trip requests or
  accepted road itineraries. Check the specific file metadata/license before
  using any extracted facts; public access alone does not establish permission
  for every training use.

3. Existing Wikidata snapshot in this project

- The project source register records structured Wikidata items under CC0 and
  permits training/evaluation after separate quality and human review.
- Current snapshot: 171 place records with English labels, types, and
  coordinates. It supplies entity facts, not route legs, opening hours,
  facilities, costs, or example itineraries.
- It can help ground examples only where the facts are sufficient and reviewed.

4. Existing OpenStreetMap snapshot in this project

- At the time of the original audit, the source-register decision allowed
  local processing, runtime search, display, attribution, and ODbL
  distribution only. A separate review dated 2026-10-18 has since approved
  training/evaluation with conditions: ODbL offers for public training data
  and OSM attribution in documentation for public models. See the follow-up
  section below and ai/data/GOVERNANCE.txt.

5. Fresh Wikidata place-fact download completed for this pilot

- Fresh source snapshot: `ai/data/processed/wikidata-karnataka/wikidata-karnataka-20261018t154918573970z/`.
- It contains 171 records: 159 attractions and 12 hotels. Restaurant and
  fuel-station queries returned no accepted records.
- A Bengaluru-centered 250 km great-circle subset was created at
  `ai/data/processed/wikidata-bengaluru-250km/wikidata-bengaluru-250km-20261018/`.
  It contains 86 records: 75 attractions and 11 hotels.
- The subset is a geographic prefilter, not a road-distance guarantee. The
  extract is Karnataka administrative membership only, so it does not include
  nearby places across state borders.
- Both generated snapshots are ignored by Git, preserve source metadata and
  hashes, and remain pending quality review. They contain zero trip-planning
  training examples.

What this means for dataset creation

The first useful trip-planning supervision must be built from complete cases,
not from place-name Q&A alone. For every case, retain:

- The request with duration, route endpoints, dates, vehicle, daily driving
  limit, budget scope, pace, interests, facilities, and exclusions.
- Route and stop facts from sources explicitly approved for training, with
  immutable snapshot IDs and evidence references.
- A human-written/reviewed reference itinerary containing exact POI IDs,
  day/stop ordering, feasible times, grounded reasons, and stated unknowns.
- A scenario family, corridor group, source IDs, reviewer, and review outcome.

Recommended collection order:

1. Start with 10–20 cases over 2–3 representative Bengaluru corridors, using
   only facts whose sources allow model training. Treat these as a data-pipeline
   pilot, not a quality claim.
2. Add cases for different duration, vehicle, pace, budget, facility, and
   uncertainty constraints. Keep source snapshots and routes traceable.
3. Create a separate human-reviewed holdout set before training. Group related
   cases by corridor, source snapshot, and scenario family to avoid leakage.
4. Ask users for explicit model-training opt-in before using their requests,
   itinerary edits, accepted plans, ratings, or trip history.
5. Run the base instruction model against the holdout first. Fine-tune only
   after the failures show a learnable pattern and the dataset has enough
   diverse, reviewed examples.

Immediate source action

Before collecting real examples from OGD, download the exact resource and
preserve its catalog metadata, license, attribution, hash, and source record.
Confirm that it contains route-relevant place records rather than only counts.
The OSM training/evaluation source-use review has now been updated; comply
with its ODbL data-offer and model-attribution conditions before public model
use. For Wikidata, review individual places and correct names/types before
using them in reference itineraries.

This audit is a project data-engineering assessment, not legal advice. It does
not establish that a source is suitable merely because the source is public.

- The official Karnataka OGD `Transport GIS Dataset` describes road and rail
  geospatial layers and is listed under NDSAP. Its catalog is dated 2021, its
  linked resource pages report that download requires registration, and the
  catalog currently shows no resource result. Do not ingest it until the
  actual file, specific license/terms, freshness, and route suitability are
  verified. Catalog: https://karnataka.data.gov.in/catalog/transport-gis-dataset
- The TravelPlanner benchmark repository offers 45 human-annotated training
  query/plan pairs, but these are US multi-mode itineraries rather than Indian
  road trips. Inspection of a published example showed place/city and lodging
  inconsistencies. Do not use these as factual or route-planning supervision.
  The Hugging Face dataset card identifies CC-BY-4.0, but that permission does
  not fix domain mismatch or data quality. References:
  https://huggingface.co/datasets/35597Q/TravelPlanner
  https://raw.githubusercontent.com/OSU-NLP-Group/TravelPlanner/main/finetuning_data/std_travelplanner.jsonl

  17,638 schema-valid records across Karnataka, including 8,607 restaurants,
  2,359 hotels, 1,220 fuel stations, 436 attractions, 61 restrooms, and
  89 viewpoints. Brand scan passed. Data is under the ignored
  `ai/data/processed/karnataka-2026-10-17/` directory.
- A separate OSMF guidance review now permits local training/evaluation and
  public model use conditionally. The OSM-derived training/evaluation dataset
  must be made available under ODbL with attribution and reproducible source
  materials, and model documentation must attribute OSM. The project's source
  register records the condition. References:
  https://osmfoundation.org/wiki/Licence/Attribution_Guidelines#Machine_learning_models
  https://osmfoundation.org/wiki/Licence/Licence_and_Legal_FAQ
- The current extractions are still source facts, not human-reviewed trip
